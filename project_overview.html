Dig-AI-FTE Project Overview

Project Introduction

DIG-AI-FTE (Digital AI - Full-Time Equivalent) is an autonomous AI employee system that combines automated workspace monitoring with intelligent skill dispatch capabilities. The system features Human-in-the-Loop (HITL) approval for high-risk operations, ensuring safety while maintaining autonomous operation for routine tasks.

Built using Python 3.11+ with production-grade infrastructure (PM2 process management, atomic state management, comprehensive logging), the system follows Spec-Driven Development (SDD) principles and provides real-time CEO dashboard tracking via Obsidian integration.

Key Features

🔍 Autonomous Error Detection

Status: ✅ Complete & Tested

Real-time pattern matching in log files using regex. Detects TypeError, AttributeError, test failures, and completion claims. Includes deduplication (30s window) and debouncing to prevent event spam. ReDoS prevention validates all patterns before compilation.

Skills: EventDetector, Debouncer, EventHasher, RegexValidator

🛡️ Human-in-the-Loop (HITL) Approval

Status: ✅ Complete & Tested

High-risk skills require explicit human approval before execution. File-based approval workflow with JSON requests in .approvals/ directory. CLI interface for approve/reject decisions. Risk assessment, timeout handling, and user identity tracking included.

Skills: HITLApprovalManager, CLI Commands (approve/reject/list)

🎯 Security Allowlist

Status: ✅ Complete

Only pre-approved skills can execute (5 skills whitelisted). Risk classification (low/medium/high). High-risk skills automatically require HITL approval. Unauthorized skill attempts are logged and blocked.

Config: allowed_skills.yaml | Validator: ConfigManager

📊 Real-time Workspace Monitoring

Status: ✅ Complete

Monitors /specs directory for changes using watchdog library. Automatically updates Factory_Board.md and SDD_Tracker.md based on YAML metadata. Alphabetical processing order. State persistence with .observer_state.json.

Service: workspace-observer (PM2 managed)

⚙️ Production Infrastructure

Status: ✅ Complete

PM2 process management with auto-restart on failure. File-based locking (fcntl) prevents race conditions. Atomic state management with JSON persistence. Logging with 90-day retention and gzip compression. Graceful shutdown handling.

Tools: PM2, LockManager, AtomicCounter, ExecutionLogger

🚨 Emergency Kill-Switch

Status: ⏳ Foundation Ready (Phase 6)

Immediately stops all skill dispatches. CLI command for activate/deactivate. State persisted in global_counter.json. Foundation implemented, full integration in Phase 6.

CLI: dispatcher kill-switch activate/deactivate/status
